토큰 소비가
왜 문제인가

Claude는 모든 입력과 출력을 "토큰" 단위로 과금합니다. Claude Code 에이전트가 도구를 쓸수록 토큰이 쌓입니다.

Claude Code
훅(Hook)이란?

Claude Code는 도구 실행 전·후에 사용자 정의 스크립트를 끼워 넣을 수 있습니다. 이게 "훅"입니다.

🔧 훅(Hook) 개념 — 중간에 필터를 끼워 원하는 결과만 통과시킨다
훅 = 파이프 중간의 밸브/필터. 명령 실행 전·후에 자동으로 개입해 불필요한 출력을 제거

등록 위치 — settings.json
~/.claude/settings.json (또는 .claude/settings.local.json)
"hooks": {
  "PreToolUse": [
    {
      "matcher": "Bash",
      "hooks": [{ "type": "command", "command": "rtk hook pre" }]
    }
  ],
  "PostToolUse": [
    {
      "matcher": "Bash",
      "hooks": [{ "type": "command", "command": "rtk hook post" }]
    }
  ]
}
🔌

훅의 활용 범위

토큰 절약 외에도 훅은 다양하게 쓸 수 있습니다:
보안 감사(위험 명령 차단) · 로깅(모든 실행 기록) · 알림(완료 시 카카오톡 발송) · 자동 포맷팅(결과 정리)

핵심 도구 · RTK

RTK
Rust Token Killer

Claude Code Bash 도구에 자동으로 끼어드는 훅 프록시입니다.
명령 실행 결과를 필터링해 Claude에게 필요한 내용만 전달합니다.

🦀

RTK가 하는 일 — 한 줄 요약

git status를 실행하면 RTK가 자동으로 rtk git status로 바꿔서 실행합니다.
결과는 동일하지만 Claude에게 돌아오는 출력은 압축·필터링되어 토큰이 줄어듭니다.

동작 원리 — Before vs After
RTK 없을 때
$ git log --oneline
a1b2c3d feat: add login
d4e5f6a fix: typo
7890abc chore: deps
... (200줄 더)
→ 전체가 Claude 입력으로
RTK 있을 때
$ rtk git log --oneline
a1b2c3d feat: add login
d4e5f6a fix: typo
7890abc chore: deps
[RTK: 197줄 생략]
→ 상위 3줄만 전달 (90% 절약)

🦀 Rust로 만든 이유

Python·Node.js 없이 단일 바이너리. 속도 오버헤드 0에 가까움. 훅이 느리면 의미 없기 때문.

🔗 훅에 자동 등록

Claude Code settings.json에 Pre/PostToolUse 훅으로 등록. 이후 모든 Bash 실행이 자동으로 RTK를 통과.

📊 사용량 추적

rtk gain 명령으로 절약된 토큰 수, 명령 횟수, 절약률을 언제든 확인.

🔍 디버그 지원

rtk proxy <cmd>로 필터링 없이 원본 출력 확인 가능. 필요 시 바이패스.

실전 · 설치 & 설정

RTK 설치
3단계면 끝

바이너리 다운로드 → 훅 등록 → 확인. Claude Code 구독이 있으면 추가 비용 없음.

1

바이너리 설치

공식 릴리스에서 OS에 맞는 바이너리를 받아 PATH에 추가

2

훅 등록

settings.json에 PreToolUse / PostToolUse 훅 등록

3

동작 확인

rtk gain으로 절약 현황 확인. Claude Code 재시작 후 즉시 적용

1. 바이너리 설치 (Linux / macOS)
# GitHub Releases에서 다운로드 후
chmod +x rtk
mv rtk ~/.local/bin/rtk
rtk --version   # 버전 확인
2. ~/.claude/settings.json 훅 등록
{
  "hooks": {
    "PreToolUse": [{
      "matcher": "Bash",
      "hooks": [{ "type": "command", "command": "rtk hook pre" }]
    }],
    "PostToolUse": [{
      "matcher": "Bash",
      "hooks": [{ "type": "command", "command": "rtk hook post" }]
    }]
  }
}
3. 메타 명령어 — 항상 rtk 직접 호출
rtk gain           # 절약 통계 보기
rtk gain --history  # 명령별 절약 이력
rtk discover       # 더 절약할 수 있는 명령 탐색
rtk proxy <cmd>   # 필터링 없이 원본 실행 (디버그)
rtk --version      # 버전 확인
⚠

주의 — 이름 충돌

rtk gain이 실패하면 다른 rtk 바이너리가 설치되어 있을 수 있습니다.
which rtk로 경로를 확인하고, ~/.local/bin/rtk가 맞는지 점검하세요.

효과 측정 · rtk gain

실제 절약
얼마나 되나

rtk gain 명령으로 언제든 확인 가능. 아래는 실사용 예시입니다.

1,001
총 명령 실행 횟수
213,000
절약된 입력 토큰
3.1%
기본 절약률
최대 90%
출력 다중 명령 시
절약률이 왜 편차가 크나
  • 짧은 명령(pwd, echo 등): 절약 거의 없음 — 원래 출력이 짧기 때문
  • 긴 출력 명령(git log, npm install, find): 60~90% 절약
  • 에이전트가 코드베이스를 탐색하는 작업일수록 효과가 극적으로 커짐
  • rtk discover를 실행하면 "이 명령에 쓰면 더 아낄 수 있다"는 힌트를 줌

🧠 AI 메모리 = 매번 새로 시작하지 않도록 규칙을 파일로 저장

📄 CLAUDE.md 란?

프로젝트 루트나 ~/.claude/에 두는 마크다운 파일. Claude가 세션 시작 시 자동으로 읽어 규칙을 주입합니다.

세션 매번 지시 반복 → CLAUDE.md로 자동화

🗄 메모리 파일

CLAUDE.md에서 외부 파일을 참조(@파일경로)하면 여러 md 파일로 분산 저장 가능. 큰 프로젝트에 유용.

훅 외에도 모델 선택, 권한, 자동승인 목록을 설정합니다. RTK 훅도 여기 등록.

운영 철학 · AI를 잘 쓰는 법

AI 에이전트
잘 쓰는 5원칙

도구가 아무리 좋아도 쓰는 방법이 틀리면 역효과. 실제 운영에서 검증된 원칙들입니다.

🎯 AI 운영 철학 — 도구를 잘 쓰려면 규칙과 습관이 필요하다
규칙 정의 → 실행 → 측정 → 개선의 반복 사이클이 AI 운영 효율을 지속적으로 높인다

① 첫 문장이 결론 — VFF 원칙

AI에게 지시할 때도, AI의 답변도 "결론 → 근거" 순서를 강제하세요. 배경 설명만 늘어놓는 답변은 CLAUDE.md에서 금지시키면 됩니다.

② 마지막 1cm는 인간이 — 자동 집행 금지

파일 삭제, 코드 배포, 결제, 이메일 발송 — 되돌리기 어려운 작업은 AI가 "준비"하고, 최종 실행은 반드시 사람이 합니다.

③ 토큰을 설계하라 — RTK + 명령 최적화

RTK 설치만으로도 절약 가능하지만, 근본적으로는 AI가 짧고 유용한 출력을 받도록 명령 자체를 설계해야 합니다. --oneline, --quiet, head -n 20 등 적극 활용.

④ 맥락은 파일에 — 구두 반복 금지

"저번에 말했잖아요" → 세션마다 잊어버립니다. 자주 쓰는 맥락은 CLAUDE.md·메모리 파일에 적어두면 AI가 매번 자동으로 읽습니다.

⑤ 보안은 습관 — 키는 .env에만

API 키, 봇 토큰, 비밀번호는 절대 코드·채팅·캡처에 포함하지 않습니다. 유출 시 즉시 재발급. 회사 자산에는 정보보안팀 승인 후 사용.

⚡ FastAPI 역할 (백엔드)
  • 데이터 API: /api/data → DB 조회 후 JSON 반환
  • 분석 실행: POST 요청 → Pandas 처리 → 결과 반환
  • 파일 처리: NAS 파일 읽기 → 가공 → 스트리밍
  • 보고서 생성: PDF·Excel 자동 생성 엔드포인트
💚 Vue.js 역할 (프론트엔드)
  • 대시보드: FastAPI 데이터 받아 Chart.js로 렌더링
  • 필터 UI: 날짜·조건 선택 → API 재호출
  • 보고서 뷰어: PDF 미리보기·다운로드 버튼
  • 실시간 갱신: WebSocket or 주기적 polling
FastAPI 기본 구조 예시
# main.py
from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware
import pandas as pd
 
app = FastAPI()
app.add_middleware(CORSMiddleware, allow_origins=["*"])
 
@app.get("/api/quality")
def get_quality(line: str, date: str):
    df = pd.read_csv(f"/nas/data/{line}_{date}.csv")
    return df.to_dict(orient="records")
Vue.js API 호출 예시
// composables/useQuality.js
import { ref } from 'vue'
import axios from 'axios'
 
export function useQuality() {
  const data = ref([])
  const fetch = async (line, date) => {
    const res = await axios.get(`/api/quality?line=${line}&date=${date}`)
    data.value = res.data
  }
  return { data, fetch }
}

Step 1. Frontend/Backend/Database 선택하기
어떤 기술을 쓸지 선택합니다. 각 조합의 장단점을 비교표와 함께 설명합니다.
• Streamlit (프런트엔드 추천) vs React vs R Shiny
• FastAPI (백엔드 추천) vs Express vs Spring Boot
• SQLite vs PostgreSQL vs Vector DB
Step 2. FastAPI + Streamlit 로컬 개발
5분 안에 백엔드 + 프런트엔드를 로컬에서 띄웁니다.
• python main.py → FastAPI 백엔드 실행
• streamlit run app.py → Streamlit 프런트엔드 실행
• http://localhost:8501에서 채팅 인터페이스 테스트
Step 3. SQLite 데이터베이스 연동
사용자의 질문과 GPT 응답을 데이터베이스에 자동 저장합니다.
• 테이블 자동 생성 (초기화)
• 트랜잭션 관리 및 에러 핸들링
• /history 엔드포인트로 과거 대화 조회
Step 4. Docker로 프로덕션 배포
docker-compose up -d 한 줄로 배포 완성.
• 백엔드 + 프런트엔드 자동 빌드
• 포트 8000 (API) + 80 (웹UI) 자동 설정
• 헬스 체크 및 자동 재시작 포함
