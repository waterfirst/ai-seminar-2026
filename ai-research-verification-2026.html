AI 오발동 케이스 — 날짜 추론 버그

🐛 버그 패턴 (세 번 반복)

크론잡 프롬프트: "전일 코스피 데이터 확인 후 경보" AI의 행동: 1. "전일"을 스스로 추론 → 날짜 계산 오류 2. 6/10 데이터 조회해야 하는데 6/9 데이터 사용 3. 8,097(반등일)을 기준으로 "매도 권고" 발동 실제: 6/10은 7,731 (하락일) → 매도 필요 없음 → 오발동!

❌ 잘못된 설계

프롬프트: "전일 데이터 확인해라" → AI가 날짜 자체 추론 → 버그 발생

✅ 수정 후

1단계: --currenttime 으로 날짜 확인 2단계: 웹검색 '코스피 [확인된 날짜]' → 추론 없음 → 버그 없음

💡 LLM은 날짜/숫자를 "계산"하지 않고 "생성"한다. 항상 서버 시간을 먼저 확인시켜야 한다.

왜 코드가 세야 하나

LLM의 패턴 완성 편향

질문: "6/5, 6/8, 6/10 — 몇 연속?" AI가 하는 것: "3일 연속"이라는 패턴을 완성하려 함 6/9(리셋)을 무시하고 연속으로 이어 붙임 실제: 2일 + 리셋 + 1일

코드가 세면

def count_consecutive_dual_selling(df): streak = 0 for _, row in df.iterrows(): if row['foreign'] < 0 and row['inst'] < 0: streak += 1 else: streak = 0 # 리셋 return streak # 6/9: 기관 +25,048 → streak = 0 (리셋) # 6/10: 외+기 동시 매도 → streak = 1 # 정확한 답: 1일차

AI의 역할: 숫자를 해석하고 맥락을 이해하는 것
카운팅, 날짜 계산, 연속성 판정은 반드시 코드에게

몬테카를로 시뮬레이션 — 패턴이 진짜인지 확인하는 법

사례: KOSPI 4고점 지수피팅

4개 고점(3228 → 4226 → 6347 → 8933)을 지수 피팅하면 R²=0.997 — 패턴이 정말 있나, 아니면 우연인가?

y = 2159.9 × e^(0.0034x) R² = 0.997 간격: 113, 95, 115, 95일 CV(간격) = 0.093

눈으로 보면 완벽한 패턴
그런데... 4개 점으로 충분한가?
우연히도 이렇게 나올 수 있지 않을까?

검증 방법

"아무 패턴 없는 랜덤 상승장 2,000개를 만들고, 거기서 4개 고점을 뽑으면 R²가 얼마나 자주 0.997을 넘는가?"

몬테카를로 결과 — p값이 알려주는 것

GBM(기하브라운운동) 2,000회 시뮬레이션 각 시뮬레이션에서 4개 고점 추출 → 동일 방식으로 피팅
검정 항목우연 발생률해석
R² > 0.9972.7%드물지만 불가능하진 않음
간격 규칙성 (CV ≤ 0.093)27.8%흔함
두 조건 동시p ≈ 0.01100번에 1번 우연

✅ "완전한 착시는 아니다"

p=0.01은 통계적으로 유의미. 순수 우연으로 치부하기 어렵다.

⚠️ "그래서 돈을 걸진 않는다"

p=0.01짜리 관찰 하나로 포지션을 잡는 건 충분하지 않다. 관찰로 등록, 매매 연결 금지.

H10 사전등록 — 관찰을 가설로 바꾸는 방법

등록 내용

가설 H10: KOSPI 사이클 고점은 분기 실적 시즌 주기(~95일)로 형성 사전등록일: 2026-06-11 예측: day ~513 ± 15 = 2026년 8월 말 ~ 9월 중순 판정 기준: ✅ 적중: 2026년 8월 중순 ~ 9월 말에 지역 고점 형성 ❌ 기각: 그 외 시점 ★ 매매 연결 금지: p=0.01 관찰 하나로 포지션 변경 불가

💡 메커니즘 추론: "분기 실적이 고점을 만든다" — 이건 수비학이 아니라 검증 가능한 메커니즘이다. 맞으면 논문, 틀리면 교훈.

⚠️ 한계: 4번째 점(8,933)이 최종 고점이 아닐 수 있다. 8,933을 넘으면 피팅 재계산 필요.

🤖 AI 거버넌스 — 역할 분리

AI가 불량 경보를 낼 때: 경보와 판단을 분리. AI는 "이상 감지"만. 실제 라인 정지 결정은 엔지니어가.

직접 해보기 — 가설 사전등록 3단계

1

가설을 데이터 보기 전에 쓴다

"온도 X에서 Y 특성이 Z% 이상 변할 것이다"
2

기각 조건을 명시한다

"만약 결과가 ___이면 이 가설은 기각한다" → 나중에 "그럴 줄 알았다" 금지
3

데이터 얻은 후 판정 기록

"[날짜] 데이터: [결과]. 판정: ✅ 적중 / ❌ 기각" → AI가 판정 도와줌, 최종 판단은 엔지니어

도구: Claude Code / 노션 / 엑셀 아무거나. 중요한 건 순서다 — 가설 먼저, 데이터 나중.

이번 사이클에서 배운 것

1️⃣ 데이터에 반응하라, 서사에 반응하지 마라
    — "분명히 반등할 거야"가 아니라 수급 데이터가 말할 때까지 기다린다

2️⃣ AI는 날짜를 추론하면 안 된다
    — 항상 서버 시간을 먼저 확인. 계산이 아니라 조회.

3️⃣ 카운팅은 코드, 해석은 모델
    — 연속성 판정, 날짜 계산을 AI에게 맡기면 패턴 완성 오류 발생

4️⃣ 기각이 성공이다
    — H8 감쇠진동자 기각 = 모델이 틀렸다는 걸 확인한 것. 과학적 진전.

5️⃣ p=0.01은 관찰이지 행동 지시가 아니다
    — 통계적 유의성이 있어도 실제 의사결정엔 더 많은 증거가 필요
