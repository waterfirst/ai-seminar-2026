AI 오발동 — 날짜 추론 버그

🐛 버그 패턴 (3회 반복)

크론잡 프롬프트: "전일 코스피 데이터 확인 후 경보" AI 행동: 1. "전일"을 스스로 추론 → 날짜 계산 오류 2. 6/10 데이터 조회해야 하는데 6/9 사용 3. 8,097(반등일) 기준 "매도 권고" 발동 실제: 6/10 = 7,731 (하락일) → 매도 필요 없음 → 오발동!

❌ 잘못된 설계

"전일 데이터 확인해라" → AI가 날짜 자체 추론 → 패턴 완성 오류

✅ 수정 후

1단계: --currenttime → "2026-06-10" 2단계: 웹검색 '코스피 2026-06-10' → 7,731 (정확) 3단계: 판단 (추론 없음)

💡 LLM은 날짜를 "계산"하지 않고 "생성"한다. 항상 서버 시간을 먼저 확인시켜야 한다.

🤖 AI 거버넌스 — 경보/판단 분리

불량 감지 AI는 "이상 감지"만. 실제 라인 정지 결정은 반드시 엔지니어가. AI 오발동은 생산 손실로 직결된다. 권한 구조 설계 필수.

직접 해보기 — 가설 사전등록 3단계

1가설을 데이터 보기 전에 쓴다

"[조건 X]에서 [특성 Y]가 [방향/크기]로 변할 것이다" 예: "Poly-IGO 결정화 온도 380°C에서 이동도 > 15 cm²/Vs"

2기각 조건을 명시한다

"만약 [결과]이면 이 가설은 기각한다" → 나중에 "그럴 줄 알았다" 금지 (HARKing 방지)

3데이터 후 판정을 기록한다

"[날짜] 결과: [값]. 판정: ✅ 적중 / ❌ 기각" → Claude가 판정 도와줌. 최종 결정은 엔지니어.

도구: Claude Code / 노션 / 엑셀 — 중요한 건 순서다 (가설 먼저, 데이터 나중)

이번 사이클 — 5가지 교훈

1. 데이터에 반응하라, 서사에 반응하지 마라
   "분명히 반등할 거야"가 아니라 수급 데이터가 말할 때까지 기다린다

2. AI는 날짜를 추론하면 안 된다
   항상 서버 시간을 먼저 확인. 계산이 아니라 조회.

3. 카운팅은 코드, 해석은 모델
   연속성 판정·날짜 계산을 AI에게 맡기면 패턴 완성 오류 발생

4. 기각이 성공이다
   H8 감쇠진동자 기각 = 모델이 틀렸다는 걸 확인. 과학적 진전.

5. p=0.01은 관찰이지 행동 지시가 아니다
   통계적 유의성 ≠ 충분한 근거. 관찰로 등록, 매매 연결 금지.
