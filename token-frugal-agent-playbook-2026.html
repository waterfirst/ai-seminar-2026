우리의 낭비는 토큰 밖에서 시작된다

데이터가 흩어진다

EDM 폴더가 관리되지 않고, 같은 원천을 각자의 Excel로 다시 정리한다.

코드를 다시 만든다

앞사람의 코드를 찾지 못해 비슷한 SQL·전처리·차트를 AI에게 다시 시킨다.

배포가 개인에게 남는다

정적 페이지는 제한적이고, 동적 앱은 개인 단말기·IP·포트에 의존한다.

YMS·Cubic→개인 Excel→개인 EDM→AI 재생성→개인 배포
문제는 AI를 많이 쓰는 것이 아니라, 조직이 이미 만든 것을 찾고 다시 쓰기 어려운 것이다.
13–22분

GitHub는 저장소보다 문화다

사내 AI 조직이 사업부·팀·그룹별로 생기는 지금, 기술 표준보다 먼저 필요한 것은 발견하고 공유하고 개선하는 습관이다.

사내 Star 문화

Star는 인기투표가 아니라 “다시 쓸 가치가 있다”는 신호다.

⭐ 관심✅ 검증📦 재사용🛡 관리

계정은 비용이 아니라 기반

1,000개 계정으로는 전사 공유 문화에 한계가 있다. 작성자는 GitHub에서 협업하고, 사용자는 별도 카탈로그·배포 포털에서 결과를 소비하게 한다.

코드의 책임

README, 담당자, 입력 데이터, 실행법, 검증 결과, 최근 갱신일을 남긴다.

기여의 인정

Star보다 실제 재사용, 개선 PR, 오류 수정, 절약 시간으로 기여를 본다.

공유의 전통은 자유 소프트웨어의 철학, Linux의 분산 협업, GitHub의 Pull Request 문화로 이어졌다. 사내에서는 보안과 권한을 갖춘 innersource로 적용할 수 있다.

22–31분

AI 시대에는 데이터 품질이 먼저다

AI가 코드를 빨리 만들수록 잘못된 컬럼·단위·집계 기준도 더 빨리 퍼진다.

원천은 그대로

YMS·Cubic은 공식 원천으로 보존하고, 임의 복사본을 새로운 원본으로 만들지 않는다.

분석은 Long Format

시간 / 제품 / 공정 / 설비 / 항목 / 값 / 단위 중심으로 공통 분석 계층을 만든다.

Information Label

테이블과 컬럼에 의미, 단위, 오너, 보안등급, 갱신주기, 품질검사를 붙인다.

출력은 자유롭게

보고 단계에서는 Pivot·Excel·HTML을 허용하되, 계산 근거와 데이터 버전은 추적 가능하게 한다.

필수 정보질문
Owner누가 정의하고 오류를 승인하는가?
Meaning & Unit이 컬럼과 값의 정확한 의미는 무엇인가?
Lineage어느 테이블과 로직에서 만들어졌는가?
Quality결측·중복·범위·시점 검사를 통과했는가?
31–37분

PPT·Word 중심에서 Markdown·HTML 병행으로

Markdown으로 지시

목적, 입력, 산출물, 제약, 완료 기준을 짧은 작업 문서로 남긴다.

Skill로 재사용

반복되는 분석법·검증법·보고서 절차를 토큰 절약 Skill로 만든다.

HTML로 공유

검색·링크·필터·재생성이 가능한 살아 있는 보고서를 만들고, PPT·Word는 승인·대외 보고에 병행한다.

PPT를 없애자는 것이 아니다. 재사용 가능한 업무 지식의 원본을 Markdown·코드·HTML로 남기자는 것이다.

47–50분

제가 드리고 싶은 짧은 제안

저는 AI 조직이나 제도를 만드는 사람이 아니라 현장에서 AI를 써 본 엔지니어입니다. 그래서 거창한 조직개편보다 작은 실험을 제안합니다.

1. GitHub 접근 확대 검토

계정 사용 실태를 보고, 공유·검토가 필요한 엔지니어부터 확대한다.

2. 공통 데이터 표준 파일럿

YMS·Cubic 핵심 테이블부터 label과 long-format 예시를 만든다.

3. 사내 코드 카탈로그

좋은 코드와 Skill을 검색하고 추천하고 재사용할 작은 공간을 연다.

4. 경량 배포 통로

개인 PC가 아닌, 검증된 소규모 앱을 올릴 공용 경로를 시험한다.
