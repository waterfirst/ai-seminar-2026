삼성디스플레이 품질팀 실전

품질팀 AI 실무 세미나

검색형 AI를 넘어서, 일하는 AI 팀 만들기. 품질팀이 실제로 자주 부딪히는 문서, 데이터, 보고서, 법령, 서버, 반복업무를 AI와 MCP, 멀티에이전트로 어떻게 줄일지 실무형으로 정리했다.

왜 필요한가 검색형 AI의 한계 MCP 웹앱 vs MCP 실무 사례 멀티에이전트 토큰 절약 팀 서버 도입 로드맵
Why Now

왜 지금 품질팀에 AI가 필요한가

문서 병목

  • 보고서 초안
  • 고객 대응 문안
  • 긴 PDF/HWP 정리

데이터 병목

  • 엑셀 정리
  • SQL 초안
  • 장기 데이터 누적

판단 병목

  • 법규/기준서 확인
  • 최신 정보 확인
  • 반복 질의 응답

핵심은 “AI가 똑똑하냐”가 아니라 “품질팀 일을 실제로 줄여주냐”다.

Limit

검색형 AI만 쓰면 생기는 문제

자주 생기는 실패

  • 그럴듯하게 틀림
  • 옛날 통계를 최신처럼 말함
  • 규정/법령을 안 읽고 아는 척함
  • 표와 공문서 구조를 잘 못 읽음

결론

AI를 더 말 잘하게 만드는 것보다,
AI가 직접 확인해야 할 자료에 닿게 만드는 구조가 중요하다.

MCP

MCP와 연결형 AI

법령

법제처 API로 법령 검색, 본문 확인, 변경 감시

공문서

kordoc으로 HWP/HWPX/PDF/엑셀을 AI가 읽을 수 있게 변환

통계

KOSIS, 공공데이터를 실시간 조회

특허

KIPRIS 기반 특허·상표 검색으로 이름/아이디어 확인

AI가 "기억으로 대답"하지 않고 필요한 자료를 직접 확인하게 만드는 연결 규칙 = MCP

품질팀 기준으로 MCP가 필요한 이유

  • 품질팀은 "질문"보다 확인이 중요하다
  • 법규, 기준서, 공문, 통계, 특허를 원문 기준으로 봐야 한다
  • 엑셀/HWP/PDF를 매번 사람이 열어보는 시간이 오래 걸린다
  • AI가 직접 자료를 읽게 하면 반복 설명과 복붙이 줄어든다

품질팀에서 바로 체감되는 효과

  • 기준서 비교 속도 상승
  • 법규 변경 추적 자동화
  • 고객사/사내 문서 액션 아이템 추출
  • 특허/상표 선행 확인 시간 단축

품질팀용 MCP 상세 가이드

1단계 — 먼저 읽게 만들기

  • kordoc으로 HWP/HWPX/PDF/엑셀을 읽게 한다
  • 회의자료, 공문, 고객 문서를 Markdown 형태로 바꾼다
  • 이 단계만 해도 "요약/액션 추출/비교"가 가능해진다

2단계 — 공식 출처에 닿게 만들기

  • korean_law로 법제처 원문 확인
  • korean_stats로 KOSIS 통계 확인
  • korean_patent로 특허/상표 선행 확인
  • 중요 숫자와 규정은 기억이 아니라 원문 기준으로 간다

3단계 — 반복 업무를 자동화하기

  • 법령 변경 감시
  • 문서 업로드 시 자동 요약
  • 월간 보고서 초안 자동 생성
  • 특정 키워드(안전, 화학, 개인정보) 포함 문서만 추출

품질팀 실전 예시 A — 법규 변경 감시

  • 대상: 산업안전보건법, 화학물질관리법, 개인정보보호법
  • MCP 흐름: 법령 검색 → 본문 조회 → 변경 조문 비교 → 영향 요약
  • 결과: "어느 조문이 바뀌었고 우리 팀이 뭘 봐야 하는지"를 3줄로 받는다

품질팀 실전 예시 B — HWP 공문 처리

  • 대상: 협력사 공문, 사내 기준서, 회의자료
  • MCP 흐름: kordoc 변환 → 액션 아이템 추출 → 담당별 분류
  • 결과: "누가 무엇을 언제까지 해야 하는지" 자동 정리

품질팀 도입 순서

1. kordoc부터 붙인다 2. korean_law / korean_stats / korean_patent를 붙인다 3. 읽기 전용으로 먼저 쓴다 4. 익숙해지면 자동 요약/감시로 확장한다 5. 마지막에 팀 서버와 연결한다

처음부터 다 자동화하려고 하지 말고, 읽기 → 확인 → 비교 → 감시 순서로 올라가는 것이 가장 안전하고 실용적이다.

Web App vs MCP

웹앱을 만들 것인가, MCP를 만들 것인가

핵심 비유

웹앱은 인간이 들어가서 직접 쓰는 독립된 방이고,

MCP는 AI 비서에게 쥐여주는 전문 도구 세트다.

품질팀 실무 기준 한 줄 판단

사람 여러 명이 직접 들어가 보는 화면이 필요하면 웹앱,

AI가 문맥을 읽고 바로 실행하게 만들려면 MCP가 더 강하다.

구분 웹앱 MCP
사용자 인터페이스 (UI) 개발자가 만든 자체 웹 페이지 / 앱 화면 AI 대화창 (Claude, Cursor, Codex 등)
조작 주체 인간이 직접 클릭하고 입력 AI가 문맥을 파악해 직접 호출
데이터 연동 방식 클라우드 API 중심, 로그인 필요 로컬 PC/사내망 파일, DB와 표준화된 통로로 연결 가능
컨텍스트 활용 이전 대화나 나의 상황을 모름 기존 대화, 로컬 가이드라인, 파일 맥락을 반영 가능

예시: 코드 스타일 검사기

  • 웹앱: 로그인 → 코드 붙여넣기 → 버튼 클릭 → 결과 확인
  • MCP: UI 없이 규칙(Resource) + 검사 기능(Tool)만 연결
  • 그 다음부터는 Claude/Cursor/Codex가 코드를 보며 자동으로 규칙을 적용

품질팀에서의 선택 기준

  • 웹앱: 팀원이 직접 보는 대시보드, 리포트 화면, 공용 포털
  • MCP: 법령 조회, 문서 파싱, DB 조회, 보고서 초안화, 내부 규칙 적용
  • 현실적으론 웹앱 + MCP를 같이 쓰는 구조가 가장 강함

품질팀 예시 1 — 불량/수율 대시보드

웹앱이 더 어울리는 경우

  • 여러 명이 같이 보는 화면
  • Lot별 추이, 불량 Pareto, 기간 비교
  • 회의 때 바로 띄우는 공용 화면

즉, 사람이 직접 보고 클릭하는 공용 화면은 웹앱이 강하다.

품질팀 예시 2 — 기준서/법규 확인

MCP가 더 어울리는 경우

  • “산안법에서 보호구 관련 조문 보여줘”
  • “이번 개정에서 바뀐 조문만 요약해줘”
  • “이 HWP 공문에서 우리 팀 액션 아이템만 뽑아줘”

즉, AI가 문맥을 읽고 자료를 직접 확인해야 하는 일은 MCP가 강하다.

품질팀 기준으로 가장 현실적인 구조

웹앱 = 팀이 직접 보는 공용 대시보드 MCP = AI가 직접 쓰는 내부 도구 예: - 웹앱: CUBIC 장기 데이터 추이 화면 - MCP: "최근 3개월 수율 저하 원인 후보 정리", "고객 대응 문안 초안", "법령 변경 감시"

결론적으로 품질팀은 웹앱과 MCP 중 하나만 고르는 것이 아니라, 화면은 웹앱으로 만들고 그 뒤의 판단/검색/초안화는 MCP로 붙이는 쪽이 가장 강하다.

결론

AI는 검색창이 아니다.
